# 门神前端重设计

目标：让群管理员快速识别待处理事项、检查防护配置、追溯判定并完成处置。覆盖桌面管理台、Telegram Mini App、公开验证与申诉页。

## 设计约定

- 使用 React 19、Tailwind 4、Base UI、TanStack Query 与现有 Lucide 图标，不增加 UI 依赖。
- 墨绿导航与青绿主色，雾白内容背景，不透明面板与轻边界。暗色模式使用同一套语义 token。
- 页面标题 24–28px，正文 14–16px，辅助文字 12–13px；数字使用等宽数字。控件圆角 6–8px、面板 12px，间距以 4px 为基准。
- 桌面端以任务分组导航，工作台突出待办、近 24 小时数据和机器人状态。列表把筛选、结果数、批量动作放在同一操作区。
- Mini App 使用固定安全区底栏和明确的返回路径；详情与表单复用同一设计语言。
- 公开页明确验证目的、当前步骤、结果和下一步；签名校验、验证码与隐私提示保持有效。
- 保留服务端权限与鉴权边界，复用现有 API。所有统计来自真实响应，不生成装饰性图表或假趋势。

## 实施与验收

1. 重做全局主题、桌面外壳、公共控件和工作台；删除液态玻璃渲染依赖。
2. 重组桌面列表、设置表单和详情操作，补齐导航与筛选反馈。
3. 重做 Mini App 顶栏、底栏、工作台、我的与公共列表表单。
4. 重做公开验证、申诉、记录查看及错误状态。
5. 使用现有 Vitest 测试覆盖行为变化，运行 lint、完整测试、类型检查与三入口构建；浏览器验证桌面、窄屏、暗色、键盘和失败态。
6. 完成 beads 状态更新，提交并推送工作分支。
